# Deterministic Replay (Commit 35)

The deterministic replay test runs the same bounded historical experiment twice against fresh stores and an identical recorded model response. Each run now returns the exact ordered context snapshots and audit events in addition to its agent invocations, findings, governance decisions, trade candidates, fills, and portfolio snapshots. Context snapshots retain their content hashes and source references, allowing a reviewer to prove what each agent could see at every simulation timestamp. The model fixture fails when it receives an unrecorded context, preventing a changed prompt input from being mistaken for a valid replay. The test independently compares invocation order, memory and governance events, research outputs, trade decisions, execution results, and portfolio state. It also verifies that snapshot identifiers equal their content hashes and that all snapshot times remain inside the historical window. Repeated context requests are retained in observation order rather than collapsed merely because their content is identical. This creates a stable regression boundary for later orchestration, caching, and model changes without relying on live nondeterministic inference.
