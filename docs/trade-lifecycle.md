# Trade Lifecycle (Commit 32)

The trade lifecycle provides one deterministic, audited route from a research proposal to a closed simulated position. Every candidate must enter the lifecycle as `PROPOSED`, then pass through `RISK_REVIEWED` before it can be approved or rejected. An approved candidate must become `SUBMITTED` before it can become `FILLED`, and only a filled candidate can become `CLOSED`. Rejected and closed candidates are terminal, so they cannot silently re-enter execution. Skipped, reversed, duplicate, unknown, and chronologically backdated transitions fail without changing lifecycle state. Each successful transition creates an immutable audit event containing the candidate ID, previous status, new status, reason, actor, run, and timestamp when supplied. Candidate objects remain immutable; each transition produces a new version held by the lifecycle source of truth. This prevents agents or execution code from bypassing risk review and makes the complete path of every simulated trade explainable and replayable.
