# Insight Attribution (Commit 39)

The lineage graph makes every research-to-execution relationship explicit and queryable. It models the ordered chain from news event to observation, insight, trade candidate, decision, and fill using stable lineage node IDs. Only adjacent stages may be connected, so an event cannot jump directly to a trade and bypass analysis or governance. Every target must be known no earlier than its source, preventing attribution links from introducing future information into a historical run. When both records identify a company, cross-company links are rejected rather than silently contaminating attribution. Nodes and nested metadata are immutable and detached from caller-owned objects, while duplicate nodes and edges fail safely. A single insight may retain multiple supporting observations and events, preserving the many-to-one evidence structure needed for honest analysis. Deterministic upstream, downstream, type-filtered, and full-trace queries allow later APIs to explain why a fill exists or which outcomes came from a source. This lineage becomes the trusted input for Commit 40 PnL attribution instead of relying on string parsing or assumptions about object IDs.
