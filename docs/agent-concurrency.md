# Agent Concurrency (Commit 43)

The concurrent agent executor parallelizes independent model and read-only analysis work while preserving a single serialized mutation boundary. It accepts the deterministic plans produced by Commit 42, normalizes their order, and rejects duplicate work before creating threads. Compute callbacks run in a bounded worker pool so safe work for different companies or agents can overlap. Results are collected first, then successful commit callbacks run sequentially on the calling thread in deterministic plan order. A failed model task is isolated, recorded as a structured failure, and never reaches the commit phase. Other independent successful tasks can still be committed, avoiding an unnecessary batch-wide failure. Empty batches do no work, and configurable worker limits prevent unbounded thread creation during large historical runs. Existing backtest news and tape calculations already use parallel read-only execution while governance, shared memory, lifecycle transitions, execution, and portfolio accounting remain serialized. This separation improves throughput without allowing races to change governed state or deterministic replay results.
