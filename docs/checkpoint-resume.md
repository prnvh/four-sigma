# Simulation checkpoint and resume

`SimulationCheckpoint` captures the six state groups needed to continue a long historical run: simulation time, portfolio state, shared memory, private working-memory records, the audit-log offset, and pending runtime events. `CheckpointStore` writes this state as canonical JSON through an atomic temporary-file replacement, avoiding partially written checkpoints after interruption. Every file contains a SHA-256 checksum and strict schema version, so corruption, manual tampering, missing fields, and incompatible versions fail closed before any state is resumed. Checkpoint names are constrained to safe file names and cannot escape the configured directory. Loading returns a detached checkpoint, and `resume()` constructs a deterministic `SimulationClock` at the saved instant alongside the remaining restored state. Datetimes and domain values are converted to portable JSON rather than unsafe executable serialization. The audit offset lets the resumed runtime continue downstream audit consumption without replaying already processed events. Pending fills and triggers remain explicit records, allowing the simulation loop to schedule them after restart without moving time backward.
