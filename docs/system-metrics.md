# System metrics

`SystemMetricsCollector` derives operational telemetry from immutable audit events, context snapshots, and optional lineage. It reports average agent latency, news-event-to-decision latency, total and per-run tokens, priced cost per run and simulated day, exact context byte sizes, model-response cache hit rate, governance latency, and simulation ticks per wall-clock second. When a lineage graph is supplied, decision latency starts at the earliest connected news event; older runs fall back to audited candidate creation-to-decision timing. Token costs use explicit per-model prices and become unknown when used tokens belong to an unpriced model, preventing falsely low cost reports. Governance latency pairs are matched by immutable proposal IDs and negative time intervals fail validation. Context size is measured from the same canonical UTF-8 payload used to hash an agent's stored context. `SimulationWorkload` supplies explicit processed ticks, elapsed wall time, and simulated days so throughput and daily cost are reproducible rather than inferred from unrelated timestamps. Empty metric families return `None`, distinguishing unavailable telemetry from a genuine zero. Cached calls contribute to run count and hit rate but add no model tokens. The collector is read-only and returns one strict `SystemMetrics` record suitable for monitoring APIs and dashboards.
